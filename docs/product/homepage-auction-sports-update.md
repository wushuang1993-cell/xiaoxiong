# 小熊 App 首页竞拍与运动板块更新说明

## 数据安全

- 正式小程序数据以微信云开发数据库 `app_states/main` 为准。
- 上线前需要先确认微信云端数据已有备份，再部署云函数和小程序代码。
- 新增字段必须兼容旧数据：`pendingAuction`、`sportsLogs`、成员 `displayName` 不应覆盖旧的家务、金币、小熊目录和头像。

## 发起竞拍

- 首页原“申请兑换”入口改为“发起竞拍”。
- 点击后进入竞拍界面：先选择对方的小熊，再设置出价金币。
- 每人每天可以发起 1 次竞拍；竞拍创建后即消耗当日额度。
- 发起竞拍需要支付 1 金币手续费，手续费不退。
- 默认竞拍时长为 180 分钟，最晚截止到当天 23:59，以更早者为准。
- 对方接受后竞拍提前结束，目标小熊转给发起人，出价金币转给对方。
- 对方拒绝、发起人取消或超时流拍时，出价金币退回发起人，手续费不退。

## 出价交互

- 默认出价 1 金币。
- 点击金币按钮一次，出价 +1。
- 旁边保留数字输入框和 - / + 调整。
- 最低出价为 1 金币。
- 最高出价为当前可用金币扣除 1 金币手续费后的余额。
- 金币不足、出价过低或已达每日额度时，需要弹窗或 toast 提示。

## 登录资料

- 系统身份仍然使用 `闪闪鱼` / `杰尼龟` 作为数据 key，避免历史金币和日志错乱。
- 登录方式改为微信登录，通过云函数获取 openid。
- 首次微信登录时，用户需要绑定已有成员，或新增一个运动成员。
- 新增显示名 `displayName`，用于界面展示。
- 平时不显示名称输入框；点击名称时弹窗修改显示名。
- 平时不显示头像上传入口；点击头像时选择并上传新头像。
- 当前登录身份修改头像后，应同步到该身份的所有头像展示位置。

## 图片规范

### 人物头像

- 推荐格式：PNG、JPG、JPEG。
- 推荐尺寸：512 x 512 px。
- 最低建议：300 x 300 px。
- 建议正方形，人物主体居中，四周留 10%-15% 空白。
- 文件大小建议小于 2MB。
- App 内统一圆形裁切。

### 小熊图片

- 推荐格式：透明背景 PNG。
- 推荐尺寸：1024 x 1024 px。
- 可接受尺寸：800 x 800 px。
- 建议正方形画布，小熊主体居中，四周留 12%-18% 空白。
- 不建议自带白色方形底。

### 图片异常提示

- 图片格式不支持：请上传 PNG、JPG 或 JPEG 图片。
- 图片太大：图片不能超过 2MB。
- 图片比例不合适：建议上传正方形图片，显示效果会更好。
- 上传失败：图片上传失败，请稍后重试。

## 运动板块

- 新增独立“运动”Tab，将运动从家务日历中分离。
- 运动 Tab 使用独立运动图标，不复用日历图标。
- 运动页分为两个排行：
  - 微信步数排行：展示每个成员当天微信运动步数。
  - 运动排行：展示手动记录的健身、打球、跑步等运动分。
- 每天可按成员记录运动类型和运动时长。
- 运动项目像家务一样可以编辑设置，包括新增、删除和换算系数。
- 默认换算规则：
  - 跑步：分钟 x 1.2
  - 快走：分钟 x 0.8
  - 骑行：分钟 x 0.7
  - 游泳：分钟 x 1.4
  - 力量：分钟 x 1
  - 瑜伽：分钟 x 0.6
  - 球类：分钟 x 1.1

## 微信步数与微信登录

- 微信步数可以接入，但需要用户授权 `wx.getWeRunData`，并通过云函数解密后写入 `wechatSteps`。
- 当前版本先保留微信步数入口和手动步数补录；完整自动接入需要补云端解密和隐私授权流程。
- 微信授权登录使用云函数获取 openid 作为登录标识，再让用户绑定到 `闪闪鱼`、`杰尼龟` 或新增成员。
- 微信昵称和头像不建议直接覆盖系统身份，应作为显示名和头像来源，由用户确认后保存。
